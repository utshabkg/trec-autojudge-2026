\label{sec:submissions}

every run and every topic of its test set, which a script checked before each
upload, since a partial leaderboard is rejected.

\run{nuggetrecall-best} is our main system. Under the scoring in force at the time,
\judge{NuggetRecall} scored higher than \judge{Corroborate} on both pilots that
resemble the test sets. \run{nuggetrecall-rank} adds \texttt{NR\_RANK} to the same
judgments. We computed it from the submitted leaderboard instead of judging again,
so the run-to-run noise of Section~\ref{sec:noise} cannot enter. On rag25-gen this
computation matches the judge's own to twelve decimal places. We added
\run{nuggetrecall-gptoss} because gpt-oss-20b was our best judge on ragtime25. On
ragtime26 it left 163 of 5,041 judgments unreadable, 3.2\%, and 3 of 103 topics on
a title-only key. We added \run{ensemble-qwen-gptoss} for its gain in \tauap\ on
rag25-gen (Section~\ref{sec:ensemble}). \run{corroborate-best} is the LLM-free
method. It uses the 0.50 specificity floor, the same configuration as
\run{lead-racer}.

The two \judge{NuggetRecall} code submissions differ in one respect.
\run{grave-node} carries the growing reply budget of Section~\ref{sec:budget} and
\run{rank-dioptre} does not. We registered \run{grave-node} after seeing what a fixed
budget did to gpt-oss-20b on rag26 (Figure~\ref{fig:budget}), and asked the
organizers to treat it as our main code submission.
